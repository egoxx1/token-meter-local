# Token Meter Local 0.10.2

**사용자가 수정한 0.10.1을 기반으로 메모리 사용을 줄인 버전입니다.** Codex·Claude Code·Antigravity 수집, 입력·캐시 읽기·캐시 쓰기·출력의 비용, 재측정·전체 초기화·원본 DB 대조 기능을 유지합니다.

## 설치할 파일은 VSIX 하나

1. `token-meter-local-0.10.2.vsix`를 받습니다. 전체 묶음 ZIP을 받았다면 압축을 먼저 풉니다.
2. VS Code → 확장 → `…` → **Install from VSIX…** → 위 파일 선택.
3. 작업 저장 → **Developer: Reload Window** 실행. 기존 대시보드 탭을 닫습니다.
4. 하단 TM으로 다시 열고 **LOCAL / 0.10.2**를 확인합니다.
5. 구버전 수집기가 남아 있으면 **Token Meter: Restart Collector**를 실행합니다.

**기존 데이터를 지우거나 전체 초기화를 다시 할 필요가 없습니다.** `~/.token-meter`, `active-data.json`, `data-epochs`와 월별 로그를 유지하세요. 기본 경로가 아닌 별도 폴더를 쓰고 있다면 같은 dataDirectory 설정을 유지합니다. 원본 Codex·Claude·Antigravity 로그/DB도 건드리지 않습니다.

이전 설치의 확장 ID `local-token-meter.token-meter-local`을 유지했습니다. 버전 확인에 거대한 대시보드를 반복 요청하지 않도록 했고, 이전 수집기는 기존 인증된 정상 종료 경로로 교체합니다. 복구 대상 기록이 있으면 첫 실행은 평상시보다 오래 걸릴 수 있습니다.

이 패키지는 수동 설치용입니다. 실제 Marketplace 게시나 업데이트 배포 서버를 새로 연결한 것은 아닙니다. 원격 SSH/WSL 데이터는 로그가 있는 환경의 수집기가 읽어야 합니다.

## 무엇이 달라졌나

| 변경 | 효과 |
|---|---|
| 장부 스트리밍 읽기·쓰기 | 전체 문자열·전체 객체 복제가 동시에 겹치는 RAM 급증 완화 |
| journal 최신 인덱스 축소·동일 단가 공유 | 같은 기록과 가격 근거를 여러 벌 보관하는 비용 감소 |
| 변경 없는 초기화 원본·DB 재처리 억제 | 불필요한 계산·revision 저장 감소. 실제 오류는 숨기지 않음 |
| 경량 상태바 API·작은 버전 ping | 5초마다 상세 사용 이력 전체를 만드는 작업 제거 |
| 전체 이력 HTTP 스트리밍 | 모든 상세 객체/거대한 응답 문자열을 한꺼번에 만들지 않음 |
| worker 분할 전송·Python 큰 행 결합 개선 | BLOB와 이벤트 대량 복사로 인한 순간 메모리 감소 |
| 화면 중복 조회 방지·숨긴 탭 갱신 휴식 | 화면 갱신이 겹치지 않음. 수집은 계속 실행 |
| 수집기 RAM·저장 대기 표시 | 상태바 툴팁과 수집 검증 영역에서 사용량 확인 |

**사용자가 고친 Antigravity 본 호출/재시도 중복 처리, 16MiB BLOB 지원, 초기화 경계 및 복구 경로를 유지했습니다.** Codex/Claude 파서와 가격 계산 엔진 파일도 그대로입니다.

추가로 journal 저장 과정에서 빠졌던 accounting 메타데이터를 보존하여, 정상 기록이 초기화/복구 후 구버전으로 오인될 수 있는 경로를 수정했습니다. 진짜 구버전 기록은 재분석 대상으로 남기며, 캐시가 그 복구를 막지 않도록 했습니다.

## 실측 결과

| 동일한 2만 호출 시험 | 0.10.1 최대 RSS | 0.10.2 최대 RSS |
|---|---:|---:|
| 최초 수집 + 저장 | 844.1MiB | **413.6MiB** |
| 재시작 + 변경 없는 스캔 5회 | 532.7MiB | **165.3MiB** |
| 상태바 HTTP 조회 12회 | 659.4MiB | **182.2MiB** |
| 전체 사용 이력 JSONL 내보내기 | 2,064.7MiB | **201.9MiB** |
| 전체 초기화 + 재스캔 + 새 요청 | 1,381.9MiB | **288.7MiB** |

Linux / Node 22.16.0에서 단계마다 새 프로세스로 측정한 수집기 RSS입니다. **VS Code 전체·브라우저·별도 Python 프로세스는 포함하지 않습니다.** 실제 사용자 DB가 아닌 20,000개 생성 호출 + 20,000개 중복 단계 합성 SQLite를 사용했습니다. 20,000개 호출·입출력 합계와 전체 내보내기 300,090,444바이트를 보존했습니다. 강제 GC나 힙 상한 변경, 기록 삭제·샘플링은 하지 않았습니다.

RAM을 줄이는 대신 시작 시 스트리밍 파싱 비용으로 일부 실행 시간이 늘었습니다. 모든 동작이 빨라졌거나 모든 컴퓨터에서 같은 RAM이 된다는 뜻은 아닙니다. 자세한 수치·재현 명령·검증 한계는 [성능 보고서](docs/PERFORMANCE-0.10.2.md)에 있습니다.

## 화면의 숫자 의미

```
입력 전체 = IN(일반 입력) + CACHE READ + CACHE WRITE
OUT = THINKING을 한 번 포함한 전체 출력
TOTAL = 입력 전체 + OUT
```

API 단가는 USD / 100만 토큰 기준입니다. 화면의 금액은 **토큰 API 환산/추정액**이지 실제 구독 결제액이 아닙니다. 이번 메모리 수정에서 모델 단가를 새로 확인하거나 바꾸지 않았습니다.

캐시 쓰기 카운터가 없으면 `미기록`이고 실제 0으로 확정하지 않습니다. THINKING을 분해할 근거가 없으면 전체 출력을 유지하고 분해만 미확인으로 남깁니다. 다른 공급자/모델 가격으로 임의 대체하지 않습니다.

초기화 이후와 원본 세션 전체는 서로 다른 범위입니다. `수집 검증 · 세션 비교`에서 같은 도구·세션·기준 시각을 맞춘 뒤 비교하세요. 종료된 측정은 계속 동결됩니다.

## 메모리 확인과 내보내기

`수집 검증 · 세션 비교`의 리소스 줄 또는 VS Code TM 툴팁에서 **수집기 RAM(MiB)**을 확인합니다. OS 활동 모니터에서 보는 VS Code 전체 RAM과는 범위가 다릅니다.

내보내기는 서버에서 전부 스트리밍합니다. 지원 브라우저에서 저장 권한을 허용하면 파일로 직접 흘려 보내며, 미지원 환경에서는 Blob 다운로드로 전환합니다. **Blob fallback은 브라우저의 큰 파일 메모리를 여전히 사용할 수 있습니다.** OS 저장 대화상자는 이번 환경에서 실기 검증하지 않았습니다.

보이지 않는 대시보드 탭은 불필요한 화면 API 조회를 쉬지만, 로컬 수집과 이력 저장은 유지됩니다. PiP가 열려 있으면 화면 갱신을 계속합니다.

## 데이터·안전성

기존 ledger v2 / 월별 JSONL / active epoch 형식을 그대로 사용합니다. 중앙 DB를 새로 만드는 마이그레이션이나 자동 삭제는 없습니다. 장부 저장은 fsync 후 원자 교체, 실패 시 기존 파일 유지 원칙입니다. 깨진 JSON이나 손상된 journal을 무시하고 0으로 시작하지 않습니다.

월별 revision 파일의 모든 줄을 합산하면 중복입니다. 기존처럼 요청별 최신 수정본만 합산합니다. 가격 메타데이터는 메모리에서만 공유하며, 사용자 단가·이력·가격 출처를 삭제하지 않습니다. 프롬프트·응답·추론 본문·인증키는 새 저장 데이터에 추가하지 않습니다.

## 독립 실행

소스 ZIP의 `token-meter` 폴더에서 실행합니다. 기존 수집기는 먼저 정상 종료합니다.

```sh
node bin/cli.js stop
node bin/cli.js serve --open
```

Node.js 20+ 또는 VS Code 1.95+를 대상으로 합니다. Antigravity에는 실행 중 Node의 `node:sqlite` 또는 SQLite 모듈을 포함한 Python 3가 필요합니다. **새 외부 npm 실행 의존성은 없습니다.** 데이터·API 인증·로컬 전용 연결 설정은 기존과 같습니다.

## 개발·검증

```sh
npm test
npm run check
python3 scripts/package.py --out dist
```

업로드된 원본의 기존 테스트 395개를 먼저 실행했고, 수정 후 **431개**를 통과했습니다. UI는 기존 기능과 새 메모리/내보내기 검사 **92개**를 통과했습니다. 현재 릴리스에서 직접 실행한 범위는 [검증 보고서](docs/TEST-REPORT-0.10.2.md)에 구분합니다.

**미검증:** 사용자의 실제 DB·설치된 VS Code Extension Host·macOS/Windows·실제 청구서·브라우저 정상 탐색/CSP·OS PiP/파일 저장 권한·장기 수백만 호출 운영. 합성 회귀 테스트와 실제 임시 SQLite 시험을 이런 실기 검증으로 표현하지 않습니다.

기록 수에 비례하는 메모리는 아직 남습니다. 전체 JSON 이벤트 Map, 큰 측정 기준점, 전체 검색 정렬이 모두 상수 메모리인 제품은 아닙니다. 첫 복구/수집이 큰 경우 RAM이 다시 올라갈 수 있습니다. 이번 버전은 큰 중복·복사·조회 병목을 줄인 것이며 '항상 200MiB 이하'를 보장하지 않습니다.
