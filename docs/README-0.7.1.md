# Token Meter Local 0.7.1

**관측 모델과 실제 적용 가격표의 연결을 검증하는 버그 수정판입니다.** 가격표를 새로 늘리는 버전이 아니라, 다른 모델·공급자·요금 모드의 저장 단가 재사용과 단위 표시 혼동을 방지합니다.

## 설치 — VSIX 하나

1. `token-meter-local-0.7.1.vsix`를 받습니다.
2. VS Code → 확장 → `…` → **Install from VSIX…** → 파일 선택.
3. 작업 저장 후 **Developer: Reload Window**. 기존 브라우저 대시보드 탭을 닫습니다.
4. 하단 **TM**을 눌러 새로 열고 **LOCAL / 0.7.1**을 확인합니다. 구버전이면 **Token Meter: Restart Collector**를 실행합니다.
5. 대시보드의 **모델·단가 매칭 검사**에서 관측 모델, 적용 가격표 모델, 공급자·모드와 교정 내역을 확인합니다.

**기존 `~/.token-meter`는 삭제하지 마세요.** 실행 데이터는 기본적으로 이 폴더에 그대로 유지되며 설치 파일을 AI 프로그램 폴더로 복사하지 않습니다. VSIX는 로컬 설치용이며 Marketplace나 실제 자동 배포 서버는 연결되어 있지 않습니다.

독립 실행은 새 소스 ZIP을 풀어 **token-meter** 폴더에서 실행합니다. 같은 데이터 폴더의 이전 수집기는 먼저 종료합니다.

```sh
node bin/cli.js stop
node bin/cli.js serve --open
```

Node.js 20+가 필요합니다. Antigravity SQLite에는 실행 Node의 `node:sqlite` 또는 SQLite 모듈이 있는 Python 3가 필요합니다. `npm install`은 필요하지 않습니다.

## 확인한 문제와 수정

| 문제 | 0.7.1 처리 |
|---|---|
| 요청과 호환되지 않는 저장 단가를 재사용하면서 표시 모델만 현재 모델로 바꿀 수 있음 | 가격 규칙의 원래 모델 목록·공급자·도구 범위·모드·유효기간 검증 후 사용 |
| 특정 도구의 사용자 단가가 같은 공급자의 다른 도구까지 확장될 수 있음 | 사용자 지정 도구 범위를 우선. `provider: "*"`로 명시한 규칙만 도구 전체 적용 |
| 모델·토큰이 그대로이고 요청 시각/컨텍스트 길이만 보완되면 단가 조건이 갱신되지 않을 수 있음 | 이런 메타데이터 변경도 감지하고 요청 단위 조건으로 재계산 |
| 모델 검색 표에서 Standard/Batch/Flex를 구분하지 않음 | **요금 모드 · 조건** 열과 검색에 모드 추가 |
| 적용 단가 패널을 1,000토큰 기준으로 바꾸면 검색 표의 캐시 쓰기만 1,000 기준이 됨 | 검색 표의 모든 열을 표시된 단위인 **USD / 100만 토큰**으로 고정 |

모델 매칭은 기존의 정확한 ID와 제한된 날짜 버전 별칭만 사용합니다. 비슷한 이름의 다른 모델이나 마지막 선택 모델의 가격으로 채우지 않습니다. 잘못 저장된 단가는 해당 요청의 모델·조건에 맞는 규칙을 찾아 교체하고, 규칙이 없으면 계산 불가로 남깁니다.

이 문제들은 합성 입력과 코드 실행으로 재현했습니다. **사용자의 실제 ledger나 현재 요금 화면을 받은 것은 아니므로, 신고한 현상이 어느 경로에서 발생했는지는 아직 확정하지 않았습니다.**

## 관측 모델과 가격표 모델을 따로 확인

모델 행의 **단가 · 계산식**에는 다음을 따로 표시합니다.

- 관측 모델: 해당 요청에 기록된 모델 ID.
- 가격표 모델: 실제 가격 규칙에서 매칭된 모델 ID.
- 공급자: 관측 공급자와 가격표의 공급자, 기록된 요금 모드.
- 연결 근거: 정확한 ID 일치 / 날짜 버전 → 기본 단가 / 명시적 Google 접두사 정규화.

날짜가 붙은 버전 ID와 기본 가격표 ID가 다른 것은 지원한 별칭일 수 있습니다. 이 경우 다른 모델 요금을 숨겨 적용하는 대신 그 연결 방식을 명시합니다. **ID 일치는 토큰 원본·비공개 DB 해석·실제 청구액을 검증했다는 의미가 아닙니다.**

## 모델·단가 매칭 검사와 진단 JSON

대시보드 **가격 계산 상태 → 모델·단가 매칭 검사**는 읽기 전용입니다. 전체 누적의 최신 요청 기록을 검사하며, 별도의 재측정 기준점이나 현재 보던 기간 필터로 범위를 줄이지 않습니다.

**일치 / 불일치 / 단가 미확인 / 이전 불일치 교정**을 구분합니다. 사용자 지정 단가 및 현재 카탈로그와 값이 다른 과거 단가는 별도로 표시하며, 그 숫자 차이만으로 오류라고 판정하지 않습니다.

**검사 결과 JSON 저장**은 `token-meter-rate-audit.json`을 만듭니다. 원본 프롬프트·응답·코드·API 키·runtime 접근키를 포함하지 않습니다. 요청 ID, 시간, 모델, 단가·출처 등 메타데이터는 포함하므로 공유 전에 확인하세요.

한 번에 최대 **50,000개 요청**을 검사하고 상세는 문제 우선 **1,000건**까지만 반환합니다. 초과 시 부분 검사/상세 제한을 표시하며 전체 검사가 완료됐다고 표시하지 않습니다. 검사 버튼이 데이터를 재가격하거나 외부 서버에 전송하지 않습니다.

## 기존 기록 교정과 보존

최초 업그레이드 전 **`ledger.pre-0.7.1.json`**을 보존합니다. 실제 적용 규칙과 요청이 불일치하는 저장 단가는 거부하고 요청 조건에 맞는 규칙을 선택합니다. 바뀐 계산과 매칭 근거는 기존 **월별 usage-log의 revision**으로 남습니다. 요청의 토큰 수를 증가시키거나 보존 로그를 삭제하지 않습니다.

같은 모델·조건의 유효한 과거 단가는 단순히 최신 가격표와 다르다는 이유로 바꾸지 않습니다. 이전 버전의 공식 단가 교정 규칙도 유지합니다. 가격 출처·모델 번호의 실제 의미가 잘못 기록되어 있었던 경우까지 자동으로 알아내는 검증은 아닙니다.

**이미 종료한 측정 결과는 당시 값으로 고정**되며 자동 수정하지 않습니다. 모델·단가 검사는 전체 최신 요청을 대상으로 하므로, 별도로 동결된 종료 측정의 모든 숫자를 다시 쓰거나 검사하는 기능은 아닙니다. 모델·가격만 보완된 기록은 진행 중 재측정의 새로운 토큰 소비로 세지 않습니다.

## 기존 기능 및 한계

일반 입력·캐시 읽기·캐시 쓰기, OUT·THINKING·전체 출력·TOTAL, 각 토큰/비용, 도구별·모델별 비파괴 재측정, 비교, 사용 이력·CSV/JSONL, 가격표 갱신은 유지합니다. **1M = 1,000,000 = 100만 토큰**이고 표의 API 단가와 누적 사용금액은 별개입니다.

금액은 API 토큰 환산/추정액입니다. 실제 구독 청구·무료 크레딧·세금·캐시 시간당 저장료·멀티모달·서버 도구 요금은 완전한 계산 대상이 아닙니다. Antigravity의 비공개 DB/THINKING 필드 해석, 최신 가격 카탈로그의 모든 숫자, 실제 사용자 청구 일치를 새로 인증하는 버전이 아닙니다.

**279개 Node 테스트, 108개 UI 검사**를 통과했습니다. 실제 사용자 DB·VS Code 설치·macOS/Windows·OS PiP 실기는 미검증입니다. UI는 실행 환경의 브라우저 탐색 제한 때문에 실제 앱 파일과 실제 루프백 API를 연결하는 제한된 렌더링 하네스로 시험했습니다.
