# 캐시 쓰기와 파일 쓰기 · 0.9.1

## 다른 작업입니다

- 모델이 패치/도구 호출을 생성하는 단계: 모델 출력(OUT)에 해당할 수 있습니다.
- 도구가 `export_public_site.py`·CSS 등을 디스크에 저장하는 단계: 로컬 파일 I/O이며 서버 프롬프트 캐시 생성이 아닙니다.
- 코드·도구 결과·대화가 다음 요청에 들어가는 단계: 입력입니다. 해당 공급자의 정책과 실제 usage 카운터에 따라 일반 입력/캐시 읽기/캐시 쓰기로 구분됩니다.

캐시는 반복되는 프롬프트 앞부분의 처리를 재사용하는 기능입니다. 같은 앞부분을 이미 캐시에서 읽었다면 캐시 읽기가 커도 새로운 쓰기가 없을 수 있습니다. 코드 변경량, diff의 +/− 줄 수, 파일 저장 횟수, 기다린 시간으로 캐시 쓰기 토큰을 역산하지 않습니다.

## 공식 카운터와 수집 경로는 별개

2026-09-26에 확인한 OpenAI 공식 프롬프트 캐시 문서는 Responses usage의 `input_tokens_details.cached_tokens`, `input_tokens_details.cache_write_tokens`를 구분합니다. 캐시 쓰기는 일반 입력 요금에 같은 토큰을 추가로 이중 과금하는 항목이 아니라 해당 입력 구간의 분류입니다.

Anthropic 문서는 `cache_creation_input_tokens`와 `cache_read_input_tokens`, 일반 `input_tokens`를 구분하고, 캐시 생성 5분/1시간 세부값도 다룹니다.

공식 API가 필드를 지원한다는 사실만으로 모든 CLI 버전의 로컬 로그에도 그 필드가 있다고 가정하지 않습니다. 현 Codex 로컬 파서는 지원하는 평탄화된 `cache_write_input_tokens` 계열을 읽습니다. 명시적 OpenAI API 사용량 연동은 중첩 `input_tokens_details.cache_write_tokens`도 처리합니다. 이 버전은 사용자 원본 로그를 받아 필드를 새로 검증한 것이 아닙니다. 현재 원본에 필드가 없으면 미기록으로 남습니다.

공식 자료:
- OpenAI: https://developers.openai.com/api/docs/guides/prompt-caching
- Anthropic: https://platform.claude.com/docs/en/build-with-claude/prompt-caching

가격표에 쓰기 단가가 있더라도 usage가 없으면 쓰기 금액을 독립 산출하지 않습니다. 이번 프리뷰의 $2/$0.20/$2.50/$10은 기존 프로젝트 단가와 사용자가 제시한 예시를 사용한 테스트이며, 이번 변경에서 모든 모델의 최신 단가를 재검증했다는 뜻이 아닙니다.

## 0.9.1 표시 계약

`billingView.components`에 `usageState`, `statusLabel`, `usageUnreported`, `unreportedRecords`를 추가했습니다.

| usageState | 의미 |
|---|---|
| no-observations | 범위에 관측 기록 없음 |
| legacy-unknown | 이전 고정 결과 등에 세부 자료 없음 |
| invalid | 토큰 분류 충돌 |
| unreported | 캐시 카운터 누락 + 관측된 해당 캐시 합계 0 |
| partial | 일부 요청만 카운터 제공, 관측된 캐시 합계 양수 |
| reference | 참고 해석/미분류 잔여 입력 등의 조건 |
| reported-zero | 필요한 카운터가 제공되고 관측값 0 |
| reported | 필요한 카운터가 제공되고 양수 관측 |

`unreported`에서는 토큰을 **미기록**, 해당 캐시 비용을 **분리 불가**로 표시합니다. 단가는 확인된 값이 있으면 계속 표시합니다. `partial`은 알려진 토큰/금액을 **관측분**으로 표시합니다. 원본 카운터 기반 표시는 비공개 DB 의미나 실제 청구 검증의 인증이 아닙니다.

호환성을 위해 `tokens`, `costUsd`의 관측 누계나 기존 ledger 구조를 변경하지 않습니다. 관측 쓰기0/미기록이 혼재해도 원시 숫자는0일 수 있으므로 상태 필드 없이 읽으면 안 됩니다. 실제0이 명시된 기록과 필드 자체가 없는 기록을 구분합니다.

## 전체 금액

없는 cache write를 임의로 추정하지 않으며 일반 입력에서 캐시 쓰기로 이동시키지도 않습니다. 기존 가격 엔진은 분류되지 않은 잔여 입력을 일반 입력 요금으로 계산할 수 있습니다. 이때 전체 금액은 **참고 환산**입니다. 쓰기 비용 칸의 분리 불가는 토큰 총량이 사라졌다는 뜻이 아니라 일반/쓰기 요금 구분을 확인하지 못했다는 뜻입니다.

원본 캐시 카운터·모델·단가가 불명확하면 실제 비용은 참고 금액과 다를 수 있습니다. 사용자 전체 로그의 정확성, cache write0인 원인, 구독 추가 청구액은 캡처나 diff만으로 확정하지 않습니다. 원본 공급자 로그는 읽기만 합니다.

## 프리뷰 데이터

10개의 짧은 합성 요청: 일반 잔여입력80,474 / 캐시 읽기2,374,016 / 쓰기 카운터 없음 / 전체출력14,866. 관측 총량2,469,356, 기존 단가 기준 참고 비용$0.7844112. 화면은$0.784411로 표시합니다. 일반 잔여입력은 미기록 캐시 쓰기를 포함할 수 있습니다. 입력 중 캐시 읽기 비중은96.72%이며 요청 적중률이 아닙니다.

자동 테스트에서는 별도로 쓰기0의 명시, 양수 쓰기2,000, 카운터 누락, 여러 상태가 섞인 합계를 시험합니다. 프리뷰에 사실처럼 보이게 데이터를 만들어 맞춘 것이 아니라, 해당 테스트 입력을 앱에 명시적으로 등록한 합성 데이터 화면입니다.
