# Token Meter Local 0.7.0

**일반 입력 · 캐시 읽기 · 캐시 쓰기의 토큰/금액을 분리하고, 모델별 API 단가와 계산식을 보여 줍니다.** Codex·Claude Code·Antigravity 수집, THINKING 분해, 비파괴 재측정, 월별 사용 로그는 유지합니다.

## 설치 — VSIX 하나

1. `token-meter-local-0.7.0.vsix`를 받습니다.
2. VS Code → 확장 → `…` → **Install from VSIX…** → 받은 파일을 선택합니다.
3. 작업을 저장하고 **Developer: Reload Window**를 실행합니다. 기존 브라우저 대시보드 탭은 닫습니다.
4. 하단 **TM**을 클릭해 새로 열고 **LOCAL / 0.7.0**을 확인합니다. 구버전 수집기가 남으면 **Token Meter: Restart Collector**를 실행합니다.

**`~/.token-meter`를 지우지 마세요.** 최초 업그레이드 전에 `ledger.pre-0.7.0.json`을 만들고, 남은 원본 Codex/Claude 등의 기록을 다시 읽어 캐시 카운터 존재 여부와 요청 단위 길이를 보완합니다. 이전 사용량, 월별 수정 로그와 종료된 측정은 보존합니다. 최초 재분석에 시간이 걸릴 수 있습니다.

VSIX에는 실행 코드가 포함돼 있습니다. 소스를 각 AI 프로그램의 폴더에 복사하지 않습니다. 전체 소스 ZIP은 개발/독립 실행용, all-files ZIP은 모든 자료를 한 번에 보관하는 용도입니다. Marketplace와 운영 자동 배포 서버는 연결되지 않아 **이번 버전은 수동 설치**합니다.

## 1. IN은 세 가지 입력의 합계

```
IN = Input(일반 입력) + Cached input(캐시 읽기) + Cache writes(캐시 쓰기)
입력 비용 = 일반 입력 비용 + 캐시 읽기 비용 + 캐시 쓰기 비용
```

대시보드 상단의 기존 IN 카드는 합계를 유지합니다. 바로 아래의 **일반 입력 · 캐시 읽기 · 캐시 쓰기** 패널에서 각 항목의 원 단위 토큰 수, 사용금액, 적용 단가와 합산식을 확인합니다. **쓰기 TTL · 상세**에서는 5분/1시간/일반·TTL 미기록 쓰기를 구분합니다.

캐시 비용은 IN 비용에 이미 포함됩니다. IN 비용과 캐시 비용을 다시 더하지 않습니다. THINKING도 전체 출력의 일부입니다.

```
BILLABLE OUT = OUT(비추론) + THINKING (+ 세부 분해 미확인 출력)
TOTAL = IN + BILLABLE OUT
총비용 = 입력 비용 + 전체 출력 비용
```

### 0과 미기록은 다릅니다

원본 캐시 쓰기 카운터가 없으면 **관측된 쓰기 수와 미기록 건수**를 표시합니다. 토큰 총량만 있고 쓰기 구분이 없는 기록은 미보고분을 일반 입력으로 처리한 **참고 환산**이며, 실제 쓰기가 없었다고 보장하지 않습니다. 캐시 세부값이 합계와 충돌하면 해당 입력 비용은 확정하지 않습니다. 출력 비용은 독립적으로 유지합니다.

단가가 없는데 사용량이 0인 항목은 그 구간의 비용만 0입니다. ‘캐시 쓰기 단가 없음’은 무료라는 뜻이 아닙니다. Google의 시간당 캐시 저장료를 토큰당 쓰기 단가로 바꾸지 않습니다. Antigravity 입력/추론 필드는 계속 비공개 DB의 참고 해석입니다.

## 2. 모델별 API 단가 — 기준은 100만 토큰

**1M = 1,000,000 = 100만 토큰**입니다. 기본 표시는 `USD / 100만 토큰`이며 `1,000 토큰`으로 단위만 바꿀 수 있습니다. 이 선택은 사용금액이나 내부 가격 계산을 변경하지 않습니다.

모델별 단가 표는 다음을 함께 표시합니다.

| 항목 | 의미 |
|---|---|
| Input | 캐시를 제외한 일반 입력 단가 |
| Cached input | 캐시 읽기 단가 |
| Cache writes | 캐시 쓰기 단가; 필요한 경우 5분/1시간을 구분 |
| Output | THINKING을 포함한 전체 출력의 단가 |

**표는 해당 범위의 요청에 저장된 적용 단가**입니다. 최신 공개 카탈로그 가격과 같다고 가정하지 않습니다. 모델·공급자·Fast/Batch/Flex·장문 조건·가격 구간이 다르면 별도 그룹으로 표시하며, 하나의 평균값을 API 단가라고 표시하지 않습니다. 최신 참고 가격표는 **지원 모델 검색**에서 별도로 확인하세요.

모델 행의 **단가 · 계산식** 또는 가격표의 **근거**를 열면 입력 구분별 계산식, 기록된 단가 출처/기준일/유효기간, 장문 조건과 참고 사유를 확인합니다. 최근 사용 기록에도 단가 요약이 있으며 **계산 근거**에서 요청 단위로 검증할 수 있습니다. VS Code 상태바에 마우스를 올리면 입력 구분과 단가 그룹을 함께 볼 수 있습니다.

### GPT-6 요금 조건 보완

2026-09-25 공식 모델 페이지에서 Astra/Sol/Luna의 **요청 입력 272,000토큰 초과** 시 전체 요청의 입력·캐시 단가 2배, 출력 단가 1.5배를 확인하고 구현했습니다. **일간/세션/재측정 누적량이 272,000을 넘었다고 장문 요금을 적용하지 않습니다.**

요청 단위 길이가 없거나 하나의 누적 증가분에 여러 요청이 섞인 것으로 보이면 장문 여부를 확정하지 않고 단문 참고 단가임을 표시합니다. Fast/Batch/Flex는 실제 모드가 기록된 경우에만 적용하고 추론 강도 High/Max 자체로 배수를 붙이지 않습니다.

이전 공식 단문 참고 스냅샷과 같은 기본 단가일 때만 알려진 장문 규칙으로 보완합니다. 사용자 단가·다른 역사적 가격을 임의 교체하지 않습니다. 변경 전 값은 백업과 보존 로그에 남으며 이미 종료된 측정 결과는 자동으로 바뀌지 않습니다.

## 3. 사진의 금액과 맞는 계산 예

다음은 **Sol Standard·단문 단가, 쓰기 0을 가정한 산술 재현**입니다. 사용자 원본 기록을 읽은 결과가 아닙니다.

| 구분 | 토큰 | USD / 100만 토큰 | 사용금액 |
|---|---:|---:|---:|
| 일반 입력 | 95,207 | $2.00 | $0.190414 |
| 캐시 읽기 | 3,162,240 | $0.20 | $0.632448 |
| 캐시 쓰기 | 0 | $2.50 | $0.000000 |
| 입력 합계 | 3,257,447 | 구분별 적용 | $0.822862 |
| 전체 출력 | 22,618 | $10.00 | $0.226180 |
| 합계 | 3,280,065 | 입력 + 출력 | **$1.049042** |

전체 입력에 일반 입력 단가를 곱하면 캐시 할인 때문에 맞지 않습니다. 이 예의 캐시 읽기 비율은 약 97.08%입니다. 금액은 소수점 6자리까지, 매우 작은 금액은 최대 12자리까지 표시해 이전의 `$1.049` 같은 반올림으로 계산 근거가 가려지지 않도록 했습니다. 내부 합계는 정수 pico-USD로 계산합니다.

## 4. 저장·재측정·내보내기

기존 `ledger.json`, `measurements.json`, `usage-log/YYYY-MM.jsonl`을 유지합니다. 원본 CLI 로그/DB는 읽기만 합니다. 월별 JSONL에는 새 요청과 수정본을 계속 추가하며 자동 삭제하지 않습니다. 수정 로그의 모든 줄을 합산하지 말고 요청 ID별 최신 수정본만 사용하세요.

CSV/JSONL에는 일반 입력·캐시 읽기·캐시 쓰기(5분/1시간/일반)의 토큰과 비용, **단위 토큰 수 1,000,000·USD·각 적용 단가**를 추가했습니다. 과거 필드 `output`은 전체 출력 의미를 유지하며 THINKING을 다시 더하지 않습니다.

가격이나 캐시 분류만 보완된 과거 요청을 재측정의 새 소비로 세지 않습니다. 종료한 측정은 고정 상태를 유지합니다. 과거 고정 결과에 입력 세부 자료가 없으면 없는 이유를 표시하고 다른 화면의 단가를 남겨 보여주지 않습니다.

보존하는 것은 사용량·모델·시각·요청/세션·프로젝트·단가 등의 메타데이터입니다. **프롬프트·응답·코드·추론 본문·인증키는 보존 로그에 저장하지 않습니다.** 메타데이터와 사용자 메모도 민감할 수 있으므로 공개 공유 전 확인하세요.

## 5. 실행 조건·미지원 범위

VS Code 1.95+ 또는 독립 실행 Node.js 20+가 필요합니다. Antigravity SQLite 수집에는 실행 중인 Node의 `node:sqlite` 또는 SQLite 모듈이 있는 Python 3가 필요합니다. 알려진 `.db` 형식만 지원하고 구형 `.pb`는 지원하지 않습니다. 비공개 필드 의미를 공식 청구서와 대조한 것은 아닙니다.

독립 실행은 소스 ZIP을 풀고 **token-meter** 폴더 안에서:

```sh
node bin/cli.js serve --open
# 합성 데이터로 화면만 확인
node bin/cli.js demo --open
# 개발 검사
npm test
npm run check
```

실제 구독 추가 결제액·계정 잔여량·무료 크레딧·세금·지역 계약/할증·도구 호출료·캐시 시간당 저장료·이미지/오디오를 완전히 계산하는 회계 프로그램이 아닙니다. 전체 JSON ledger의 대규모 장기 성능, 여러 기기 동기화, 웹 채팅 수집, OS 네이티브 최상위 창은 이번 변경 대상이 아닙니다.
