# Token Meter Local 0.8.0

**진행 중인 측정도 삭제하고, 측정만 전체 삭제하거나 누적 사용량까지 0부터 초기화할 수 있습니다.** 기존 도구·모델별 재측정, IN/캐시/OUT/THINKING/전체 출력/TOTAL, 모델별 API 단가·매칭 검사와 사용 기록 기능은 유지합니다.

## 1. 설치 — VSIX 파일 하나

1. `token-meter-local-0.8.0.vsix`를 받습니다.
2. VS Code → 확장 → `…` → **Install from VSIX…** → 해당 파일 선택.
3. 작업 저장 후 **Developer: Reload Window**를 실행합니다.
4. 이전 브라우저 대시보드 탭을 닫고, 하단 **TM**으로 다시 엽니다.
5. **LOCAL / 0.8.0**인지 확인합니다. 구버전이면 **Token Meter: Restart Collector** 후 다시 엽니다.

**기존 `~/.token-meter`를 지우거나 각 AI 앱의 폴더에 소스를 복사하지 않습니다.** 버전을 설치하는 것만으로 데이터가 삭제되지는 않습니다. 이번 버전도 Marketplace/운영 배포 서버에 연결된 자동 배포가 아니라 수동 설치본입니다.

소스 ZIP은 수정·독립 실행용입니다. 압축을 풀면 내부 폴더 이름은 `token-meter`이며, 기존 수집기를 종료한 뒤 새 폴더에서 실행합니다.

```sh
node bin/cli.js stop
node bin/cli.js serve --open
```

VS Code 1.95+ 또는 독립 실행 Node.js 20+를 대상으로 합니다. Antigravity DB 읽기는 실행 Node의 `node:sqlite` 또는 SQLite 모듈을 포함한 Python 3가 필요합니다. npm 설치·빌드는 필요하지 않습니다. 실제 Windows/macOS·VS Code 설치는 이 개발 환경에서 검증하지 않았습니다.

## 2. 사진의 TEST1 같은 측정을 없애기

**재측정 · 비교 → 원하는 카드 오른쪽 아래 `삭제`.** 확인창에서 삭제 대상을 확인하고 동의 체크 → **삭제**를 누릅니다.

측정 중이어도 `종료·저장`을 먼저 누를 필요가 없습니다. 해당 측정을 목록과 활성 측정 저장소에서 제거하고, 상태바 고정·비교 선택도 해제합니다. 보고 있던 측정이 없어지면 누적 화면으로 전환합니다. 실제 Codex/Claude/Antigravity 작업을 종료하는 버튼은 아닙니다.

![합성 데이터로 실행한 진행 중 측정의 삭제 버튼](docs/delete-controls.png)

| 기능 | 바뀌는 것 | 유지되는 것 |
|---|---|---|
| 카드의 **삭제** | 선택한 측정·기준점·결과·메모 제거 | 누적 사용량·사용 이력·다른 측정 |
| 체크박스 → **선택 삭제** | 선택한 여러 측정 제거 | 미선택 측정·누적 사용량·사용 이력 |
| **측정 전체 삭제** | 진행/종료/숨김/취소 측정 전부와 고정·초기화 취소 정보 제거 | 누적 사용량·사용 이력·작업 구간·설정 |
| 대시보드 위 **전체 초기화** | 현재 누적·사용 이력·작업·측정을 비우고 새 집계를 시작 | 설정·사용자 단가·수집 경로·이전 데이터 백업·각 AI 앱 원본 |

**측정 전체 삭제**는 확인 문구 `측정 전체 삭제`를 입력하고 동의해야 실행합니다. 필터로 숨겨진 측정도 포함하므로 개수를 확인하세요. 개별/선택 삭제도 확인 없이 실행하지 않습니다.

삭제된 측정은 500개 측정 보관 한도에서 빠집니다. **삭제 취소 버튼은 없습니다.** 기존 `초기화 취소`로 삭제한 카드가 되살아나지 않도록 해당 취소 정보를 정리합니다. 직전 측정 파일은 `measurements.backup.json`에 남을 수 있습니다. 이는 디스크 흔적까지 지우는 보안 삭제 기능이 아닙니다.

## 3. 누적 사용량까지 전체 초기화

**대시보드 맨 위 `전체 초기화` → 범위·백업 안내 확인 → `전체 초기화` 입력 → 동의 체크 → `전체 초기화 실행`.**

![전체 초기화의 확인 대화상자 — 합성 데이터](docs/reset-confirmation.png)

새 활성 데이터의 IN·일반 입력·캐시·OUT·THINKING·전체 출력·TOTAL과 비용을 0부터 시작합니다. 기존 활성 사용 이력, 측정, 작업 목록은 비워지고 상태바 고정도 해제됩니다. 이후 새 사용량은 계속 수집하고 새 월별 JSONL에 보존합니다.

**원본 로그를 다시 읽거나 프로그램을 재시작해도 초기화 이전 사용량을 새 집계에 다시 더하지 않도록**, 관측한 요청 ID와 토큰 기준점, 초기화 시각을 별도로 유지합니다. 캡처/데모에서만 숫자를 0으로 바꾸는 동작이 아닙니다.

이는 현재 화면/활성 저장소를 새로 시작하는 기능이지 **원본 로그·계정 한도·실제 구독 청구액을 지우는 기능이 아닙니다.** 이미 쓴 토큰을 환불하거나 계정 할당량을 복원하지 않습니다.

기존 **`전체 0부터 재측정`**은 여전히 *비교용 기준점 측정 하나를 새로 만드는 버튼*입니다. 누적/사용 이력 전체를 비우려면 새 **`전체 초기화`**를 사용하세요.

## 4. 백업 위치와 안전장치

기본 폴더는 `~/.token-meter`입니다. 별도 데이터 폴더를 지정했다면 그 폴더에 적용됩니다.

```text
~/.token-meter/
  config.json / prices.user.json       설정·사용자 단가 유지
  active-data.json                     현재 활성 데이터 폴더를 가리키는 파일
  ledger.json / measurements.json      최초 초기화 이전 기록(기존 파일 보존)
  usage-log/                          최초 초기화 이전 사용 로그 보존
  data-epochs/
    <초기화 ID>/
      epoch.json                      초기화 시점/직전 경로
      ledger.json                     새 관측값·읽기 위치·중복 방지 기준점
      measurements.json               새 측정 기록
      usage-log/YYYY-MM.jsonl         새 월별 사용 이력
```

두 번째 초기화부터는 직전 `data-epochs/<ID>` 폴더가 백업으로 남습니다. 완료 메시지에 직전 저장 위치를 표시합니다. **Token Meter: Open Usage Log Folder** 명령은 현재 활성 로그 폴더를 엽니다.

새 데이터 파일을 준비하고 저장한 뒤 활성 포인터를 교체합니다. 준비/포인터 저장에 실패하면 이전 데이터가 활성 상태로 유지됩니다. 성공한 초기화의 포인터가 없어지거나 활성 데이터가 손상되면 과거 데이터를 자동으로 복구해 다시 합산하는 대신 오류로 중단합니다.

**`active-data.json`이나 `data-epochs`를 임의로 지우지 마세요. 초기화 후에는 0.8.0 미만으로 내리지 마세요.** 구버전은 활성 포인터를 모르므로 옛 루트 기록을 다시 표시할 수 있습니다. 자동 백업 복원·다단계 되돌리기 UI는 제공하지 않습니다. 복구 전에는 수집기를 끄고 데이터 폴더 전체를 보관하세요.

이전 기록과 중복 방지 메타데이터가 남으므로 **전체 초기화는 디스크 공간 회수나 개인정보 완전 삭제 기능이 아닙니다.** 자동 백업 삭제 정책도 없습니다.

## 5. 진행 중 요청과 수집 경계

초기화 직전 저장된 기록을 한 번 수집합니다. 이미 관측한 요청이 계속 생성 중이면 이후 확인된 **양의 토큰 증가분**만 새 집계에 포함합니다. 과거 토큰의 가격·모델·캐시 분류만 바뀐 것은 새 소비량으로 추가하지 않습니다.

처음 발견한 기록이라도 요청 시각이 초기화 이전이면 제외합니다. 시각이 없으면 어느 쪽인지 확인할 수 없어 제외하고 경고합니다. 원본에 아직 커밋되지 않은 사용량의 실제 발생 시점은 알 수 없습니다. **가능하면 실행 중인 응답이 끝나고 숫자가 반영된 뒤 전체 초기화하세요.**

초기화 이전에 시작한 요청의 증가분은 새 집계에서 초기화 경계 시각으로 표시하고, 원래 요청 시각은 `sourceTimestamp`와 경고로 보존합니다. 이는 요청의 실제 실행 시각을 새로 알아낸 것이 아닙니다.

초기화 기준점은 최대 **100,000개 관측 요청 ID**입니다. 초과하면 실행을 거부하고 데이터를 그대로 둡니다. 같은 요청의 삭제·재분석·재시작·DB 복사는 지원되는 안정 ID/카운터가 있을 때 중복을 막습니다. CLI 스키마 변경이나 식별자 자체가 바뀌는 미지원 로그까지 완벽히 판별한다고 보장하지 않습니다.

다른 탭에서 측정을 삭제/전체 초기화해도 다음 조회에서 선택·고정·과거 페이지를 정리합니다. 삭제된 측정의 내보내기는 관련 없는 전체 사용량으로 대신 바꾸지 않고 오류로 거부합니다.

## 6. VS Code 명령

- **Token Meter: Delete Measurement** — 개별 측정 선택 후 삭제 확인.
- **Token Meter: Delete All Measurements** — 확인 문구를 입력한 뒤 측정만 전체 삭제.
- **Token Meter: Reset All Usage Data** — 확인 문구를 입력한 뒤 누적·이력·작업·측정 초기화.

독립 브라우저에서도 동일한 버튼을 사용할 수 있습니다. 이번 버전에 별도의 파괴적 CLI 명령은 추가하지 않았습니다.

## 7. 기존 계산과 개인정보

단가/파서/THINKING 해석은 0.7.1을 유지합니다. 이번 변경은 가격표 전체 재검증이나 Antigravity 비공개 필드 의미 인증이 아닙니다. 비용은 API 토큰 환산/추정액이며 실제 청구액이 아닙니다. Antigravity의 구형 `.pb`, 계정 한도/실청구액, 여러 기기 합산, 네이티브 항상 위 창 등 기존 미지원 범위도 같습니다.

프롬프트·응답·코드·추론 본문·인증키를 새 사용 로그에 저장하지 않습니다. 요청/모델/프로젝트 식별자, 토큰·단가·시각과 직접 적은 메모는 백업에 남을 수 있습니다. 설정/루프백 접근키 파일은 공유하지 마세요. 삭제 API도 기존 인증·Host·Origin 검사를 통과해야 합니다.

## 8. 검증

**자동 테스트 316개, UI 검사 127개(기존 108 + 신규 19), JavaScript 58개 구문/진입점 검사**를 통과했습니다. 합성 JSONL·실제 임시 SQLite, 실제 파일 저장/루프백 HTTP와 모의 VS Code API, 제한된 브라우저 렌더링 브리지를 사용했습니다.

브라우저 직접 탐색은 실행 환경 정책에 막혔습니다. 실제 VSIX 설치, macOS/Windows, 사용자 원본 로그/계정/청구서, 브라우저 탐색/CSP/OS PiP 동작을 검증한 결과가 아닙니다. 대규모 장기 성능도 보장하지 않습니다.
