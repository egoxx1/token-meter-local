## Antigravity에서 검사한 내용

입력 15,000(일반 10,000 + 캐시 5,000), 출력 2,000(추론 1,500 + 가시 출력 500), 합계 17,000인 합성 요청을 실제 SQLite에 저장해 읽었습니다. 해당 날짜의 Gemini 3.8 Flash 참고 단가로 입력 $0.007875, 출력 $0.0075, 합계 $0.015375를 산출하고 상태바 문자열과 대조했습니다. 실제 사용자의 소비량이 아닙니다.

Native `node:sqlite`와 Python stdlib fallback에서 같은 이벤트가 나오는지, 원본 DB 본문 SHA-256이 읽기 전후 같은지, 프롬프트/코드 sentinel 및 그 base64가 ledger와 CSV에 남지 않는지 확인했습니다.

WAL에만 새 사용량을 커밋하고 DB 본문 해시가 바뀌지 않은 상태에서도 새 기록이 수집되는지 검사했습니다. 반복 스캔, 프로세스 재시작, 동일 세션 DB 복사, 단계/생성 테이블 중복, 재시도, 나중에 보완되는 요청 식별자와 시각도 확인했습니다.

모델 전환, 정확한 모델 표기 변환, 미상 숫자 enum, 출력 세부값 충돌, 캐시 쓰기 TTL 미상, 시각 누락, 깨진 protobuf, 범위 밖 카운터, 식별자 없는 단계, `.pb` 기록, 다른 DB 스키마, Python 부재, DB/WAL 심볼릭 링크, 원본 삭제 후 누적 보존과 진단 상태를 검사했습니다. 미래 가격 구간 및 잘못된 유효기간 검사도 포함합니다.

## UI와 설치 검사의 한계

UI 데모는 Codex 36개, Claude 20개, 이전 Gemini 16개, **실제 합성 SQLite에서 수집한 Antigravity 8개**, 총 80개 기록입니다. Antigravity 필터에서 두 모델과 여섯 토큰/비용 값, 원 단위 카드, 기간/프로젝트/작업 구간 필터, 내보내기, 설정, 가격표 검색, 375/430/768/1280/1440px 화면을 검사했습니다.

일반 브라우저 URL 탐색을 먼저 실행했지만 개발 환경의 관리자 정책으로 `ERR_BLOCKED_BY_ADMINISTRATOR`가 발생했습니다. 정책을 변경하지 않았습니다. HTML/CSS/JS를 빈 문서에 렌더링하고 테스트용 fetch bridge로 실제 루프백 HTTP API에 연결했습니다. 따라서 **실제 URL 탐색·브라우저 CSP까지 검증한 완전한 종단간 시험은 아닙니다.** 서버 인증/Host/Origin은 별도 실제 HTTP 테스트에 포함됩니다.

미니바는 동일 렌더러를 별도 문서에 적용했습니다. OS에서 실제 창이 항상 위에 머무르는지 검증하지 않았습니다. 스크린샷은 모두 합성 데모입니다.

VS Code API는 모의 객체로 테스트했습니다. **실제 VSIX 설치, Extension Host에서의 Antigravity DB 접근, macOS/Windows/WSL/Remote SSH 실기, 실제 계정/청구서 대조, 모든 Antigravity 버전의 호환성은 검증하지 않았습니다.**

## 남은 위험

SQLite 파일이 실제 파일이라는 것은 Google의 실제 데이터 스키마와 일치함을 증명하지 않습니다. 비공개 필드 해석의 근거와 한계는 `ANTIGRAVITY.md`에 기록했습니다. 장기간 대규모 성능, 특이한 내부 모델 enum과 새로운 protobuf 배치, 식별자 없는 병합/분기 대화, 실시간 비완료 사용량은 별도 검증이 필요합니다.

프로젝트/하위 에이전트 관계는 이번 Antigravity 수집기에서 복원하지 않습니다. 구형 `.pb`만 있는 환경은 미지원입니다. 비용은 API 참고 환산액이고 실제 구독 크레딧/추가 결제액이 아닙니다.
