# 재측정 데이터 계약 · 0.4.0

## 기본 원칙

전체 사용량 ledger와 재측정 저장소는 분리됩니다. 버튼을 눌러도 원본 로그/DB나 기존 사용량을 삭제하지 않습니다. 기준점은 기준 시각의 요청별 관측 카운터이며, 계정 전체 사용량의 참값이 아닙니다.

`baseline` 측정은 표의 초기화 버튼으로 만든 측정, `named` 측정은 이름을 입력해 만든 별도 측정입니다. 둘 다 0부터 증가분을 관측하고 종료 시 고정합니다.

## 범위

필터는 도구(provider), 과금 공급자(modelProvider), 모델(model), 추론 강도(effort), 역할(role), 프로젝트 ID(projectId)입니다. 생략은 전체, 명시한 빈 문자열은 실제 미기록 값과의 정확한 일치입니다. 같은 모델명이라도 경로나 도구가 다르면 모델 행이 구분됩니다.

모델 행 초기화는 그 행의 도구·공급자·모델·강도·역할을 정확히 선택합니다. 도구 행 초기화는 해당 도구의 모든 모델입니다. 화면에 프로젝트가 선택돼 있으면 그 프로젝트도 포함됩니다. `+ 새 측정`은 조건을 직접 조합할 수 있습니다.

재측정은 ‘오늘/이번 달’과 독립된 범위입니다. 표에서 오늘을 보고 있어도 기준점은 지금 관측된 전체 ID를 저장하고 앞으로의 증가분을 계산합니다. 재측정 상세를 보고 있을 때 별도의 글로벌 도구·프로젝트 필터를 비활성화해 모호한 중첩을 막습니다.

## 증가분 계산

시작 전 한 번 수집하고 현재 모든 관측 ID의 토큰 카운터를 저장합니다. 필터에 맞는 ID만 저장하면 나중에 모델 정보가 보완된 과거 요청이 새 사용량으로 바뀔 수 있으므로, 비대상 ID도 기준점에 포함합니다.

- 이미 기준점에 있던 ID: 현재 입력/출력의 양의 증가분만 포함합니다. 감소는 0으로 제한하고 진단합니다.
- 기준점에 없던 ID: 요청 시각이 시작 시각 이상인 기록만 포함합니다.
- 뒤늦은 과거 기록과 시각 없는 새 기록: 새 측정에 포함하지 않고 제외 개수를 표시합니다.
- 단가만 바뀌거나 캐시 구성이 바뀌었지만 입력/출력이 늘지 않음: 새로운 소비로 세지 않습니다.

입력 증가분은 일반 입력·캐시 읽기·캐시 쓰기 종류별 증가분을 사용합니다. 분류 변경으로 그 합이 입력 증가분과 맞지 않으면 입력 비용을 미정으로 표시합니다. 출력 가격은 별도 유지합니다. 출력만 증가했다면 이전 캐시 재분류에서 발생한 입력 요금을 붙이지 않습니다.

가격은 해당 요청의 저장된 단가 스냅샷을 사용합니다. 장문 단가를 지원하는 규칙에서는 작은 증가분 길이가 아니라 **전체 요청 입력 길이**로 구간을 판정합니다. 추론 토큰은 정규화된 출력의 세부 항목이며 다시 더하지 않습니다. 기존 엔진이 모르는 모델·과금 모드·장문 조건을 이 기능이 새로 알아내지는 않습니다.

원본 파서의 누락, 요청 ID 충돌, 시각 오류, 잘못된 필드 의미는 여전히 결과에 영향을 줍니다. 서버 수집 경고와 제외/불명확 개수는 측정에 보존합니다. 별도 수동 usage 연동과 CLI가 같은 요청을 중복으로 보고할 경우 공급자 간 전역 중복 제거는 기존과 같이 제공하지 않습니다.

## 종료·다시 시작·취소

종료는 한 번 더 수집한 다음 증가분 이벤트·가격·진단을 고정합니다. 이후 단가 갱신, 로그 보완, 모델 변경이 종료 결과를 바꾸지 않습니다. 마지막 모델 응답이 종료됐어도 아직 로그에 기록되지 않았다면 종료 측정에 들어가지 않을 수 있으므로 반영 여부를 확인해야 합니다.

같은 정확한 필터의 baseline을 다시 초기화하면 진행하던 baseline을 종료해 보관하고 새 baseline을 시작합니다. 더 넓은 도구 초기화는 다른 모델/이름 측정을 종료하지 않습니다. 겹치는 비교 측정을 보존하기 위한 동작입니다.

표에서는 그 행에 적용할 수 있는 가장 최근 baseline을 사용합니다. 따라서 최신 도구 초기화는 그 도구의 모델 행을 함께 0으로 표시하고, 이후 특정 모델 초기화는 해당 행만 새로 시작합니다. 개별 측정 기록 자체는 독립적으로 남습니다. 이름을 붙인 측정은 자동으로 표 기준점이 되지 않으며 ‘보기’로 상세를 선택합니다.

‘초기화 취소’는 마지막 reset 한 번에 대해 가능합니다. 새 기준점을 cancelled 고정 기록으로 남기고 직전 같은 범위 baseline 및 당시 상태바 고정을 복원합니다. 새 시작·종료·이름/메모/결과 변경 뒤에는 이전 reset 취소를 제공하지 않습니다. 연속 여러 단계 되돌리기, 완료 결과 재개, 측정 일시정지는 없습니다.

## 표시·비교·내보내기

상단 전체 누적과 표별 재측정은 별개입니다. 표의 시작 시각이 서로 다르면 표 합계를 전체 사용량으로 해석하면 안 됩니다. 특정 측정의 ‘보기’로 상단·하단바·미니바를 동일 범위로 맞출 수 있습니다. VS Code ‘상태바 고정’은 수집기 공유 상태이며 같은 데이터 디렉터리를 쓰는 창에 반영됩니다. 브라우저의 상세 선택은 독립입니다.

비교는 최대 4개, CSV/JSON 내보내기는 최대 20개입니다. 동시에 진행한 측정이 겹치면 같은 요청 증가분을 여러 측정에 포함하므로 서로 더하지 않습니다. 비교 표의 진행 중 값은 버튼을 누른 시점이며 export는 export 시점의 값입니다. 안정적인 비교에는 먼저 종료한 기록을 사용하세요.

PASS/FAIL/부분 성공은 사용자가 적은 메모이며 자동 테스트 결과를 가져오는 기능이 아닙니다. 관측 토큰/분과 알려진 비용/시간은 대기·사용자 입력·수집기 중지 시간도 포함한 경과시간을 사용합니다. 모델 생성 속도나 실작업 소요시간으로 단정하지 않습니다.

## 데이터·한도

`measurements.json` 버전 1에 진행 baseline과 종료 결과를 저장하고, 변경 전 상태를 `measurements.backup.json`에 보존합니다. 이전 앱의 v2 ledger는 그대로 유지합니다. 이전 앱으로 돌아가면 재측정 기능은 표시되지 않지만, 이 저장소를 지우지 않아야 다시 사용할 수 있습니다.

진행 중 측정은 수집기를 재시작해도 유지합니다. 꺼져 있던 동안 로그에 기록된 시작 이후 요청은 다음 수집 때 포함될 수 있습니다. 종료한 측정은 더 이상 보완하지 않습니다. OS 시간 변경/시간 동기화 오류가 있으면 경과시간·경계 판정이 달라질 수 있습니다.

동시 12개, 기록 500개, baseline당 100,000 ID 제한입니다. 숨김·취소된 측정도 기록 한도에 포함하며 자동 삭제하지 않습니다. 초과 시 새 생성 작업을 거부합니다. 영구 삭제·다중 백업·파일 가져오기 UI는 없습니다. 전체 JSON 방식이므로 장기 수십만 요청 환경의 성능/내구성은 별도 검증 대상입니다.

파일 저장 실패는 측정 변경을 되돌리고 오류를 반환합니다. 손상된 저장소는 거부합니다. 백업 복원 시 마지막 변경이 없어질 수 있으므로 수집기를 종료하고 현재 파일을 보존한 후 검토하세요.

새 저장소/내보내기에는 프롬프트나 코드 본문을 넣지 않지만 요청 ID, 프로젝트 ID, 모델, 단가, 메모는 들어갑니다. 민감한 정보가 있는 메모/프로젝트 이름은 공유 전에 확인하세요.
