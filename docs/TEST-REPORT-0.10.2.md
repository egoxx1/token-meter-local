검증일: 2026-09-27. 출발점은 사용자가 업로드한 0.10.1 소스입니다. 사용자 Mac·실제 사용량 DB·계정에 접근하지 않았습니다.

## 새 회귀 시험의 내용

`test/memory-optimization.test.js`의 36개 시험이 추가되었습니다. 순차 JSON 읽기의 작은 청크·UTF-8 경계·깨진 JSON·원자 저장 실패, journal 최소 인덱스·최신 수정본 재생·회계 메타데이터 유지, 정확한 가격 메타데이터 공유와 날짜/로컬 경계, 제한 조회 캐시, 큰 Python 한 줄 청크 결합, 기존 내보내기 결과와 스트리밍 결과의 일치, 경량 상태바의 합계 보존, 초기화 후 변경 없는 재스캔의 무저장, 동시 저장 큐, 구버전 수집기의 작은 인증 API로 교체 확인, HTTP 실패 응답, 오래된 health를 캐시하지 않음, DB 변경/수동 재분석/필요한 복구가 캐시 때문에 막히지 않음을 검사합니다.

원본의 395개 시험도 함께 실행합니다. Antigravity 559개 공유 상위 ID 보존, 생성/단계 중복 제거, 사용자가 수정한 같은 본 호출/재시도 처리, WAL 추가, 초기화·재시작, 복구 계획, 원본 SQLite/Python fallback, Codex 95개 호출과 초기화 증가분, 가격 모델 매칭, 저장 실패·인증·업데이트 서명 검사 등이 포함됩니다.

기존 테스트 중 불변 공유 단가를 수정하던 부분은 복사 후 교체로 변경했습니다. 초기화 뒤 accountingVersion이 유실돼야 통과하던 기대값은 수정된 올바른 보존 결과로 바꿨습니다. 테스트용 '다음 버전'은 현재 버전에서 계산하도록 변경하여 릴리스 번호를 올려도 기존 업데이트 검증이 깨지지 않게 했습니다. 이 변경을 테스트 삭제·회계 조건 완화로 처리하지 않았습니다.

## 성능 검증

[성능 보고서](PERFORMANCE-0.10.2.md)의 동일 20,000개 호출 시험을 실행했습니다. 입력 전체 2,219,990,000 / 출력 10,000,000 / 20,000개 호출을 유지했습니다. 20,000개 대응 단계 기록은 중복 소비로 세지 않았습니다.

최초 수집, 별도 프로세스 재시작, 상태바 HTTP 조회 12회, 전체 JSONL 300,090,444바이트 내보내기, 전체 초기화 후 새 요청 1,100토큰을 각각 검사했습니다. 수정본에서는 상태바 조회 600회도 연속 실행하여 호출·journal 개수가 늘지 않는 것을 확인했습니다. 작업마다 원문 JSON과 `/usr/bin/time -v`를 남겼습니다.

RAM 한도를 강제로 낮추거나 GC를 강제하지 않았습니다. 원본 기록/가격표/수집한 호출을 버려 메모리를 줄이지 않았습니다. 같은 합계를 유지하면서 중복 객체와 임시 버퍼를 줄였습니다.

## UI 검증의 정확한 범위

일반 브라우저 URL 탐색을 먼저 시도했지만 실행 환경 정책으로 `ERR_BLOCKED_BY_ADMINISTRATOR`가 반환됐습니다. 정책을 변경하지 않았습니다. 기존 시험 방식인 about:blank에 실제 앱 HTML/CSS/JS를 넣고 인증된 실제 루프백 HTTP 서버로 연결하는 브리지를 사용했습니다.

따라서 이는 **실제 일반 탐색·CSP까지 통과한 완전한 브라우저 종단간 시험이 아닙니다.** API 인증/Host/Origin/정적 경로/실패 응답은 별도 실제 HTTP 테스트에서 검사했습니다.

새 UI 시험은 동시 새로고침 20개에서 요청이 겹치지 않고 최대 2회로 합쳐지는 것, 숨긴 탭의 조회 휴식과 다시 보일 때 재개, 메모리 지표 범위 표시, 지원 브라우저 저장 경로의 1MiB 데이터가 Blob 없이 전달되는 것을 확인했습니다. **파일 저장기는 mock이므로 OS 파일 권한/실제 저장 선택 창은 미검증**입니다. 375/768/1440px에서 리소스 정보가 화면 밖으로 넘치지 않음을 확인했습니다. 기존 화면 시험은 430/1280px도 포함합니다.

## 패키지 검증

Python 표준 라이브러리로 source ZIP과 VSIX를 만듭니다. 버전·확장 ID·manifest·진입점·새 스트리밍/메타데이터/라인/조회 모듈·Python fallback 포함을 검사합니다. 소스와 VSIX 공통 파일의 바이트 일치 및 ZIP CRC를 별도로 검사합니다.

최종 소스 ZIP을 별도 디렉터리에 풀어 Node·구문·UI 시험을 재실행하고 결과를 전체 묶음의 `verification/`에 보관합니다. 재검사 결과/공통 파일 수는 함께 제공하는 패키지 검증 JSON이 기준입니다. 보고서는 원본 실행 로그를 대신하지 않습니다.

## 코드 보존·개인정보

`src/parsers.js`, `src/pricing.js`, `src/identity-repair.js`, `src/antigravity-sqlite.py`, `data/prices.extra.json`은 업로드 원본과 동일한 SHA-256입니다. Antigravity의 호출 식별 규칙을 다른 규칙으로 바꾸지 않았습니다. 실제 단가를 새로 검증한 릴리스가 아닙니다.

배포에는 테스트 데이터 생성 코드만 포함하고 실제 사용자 DB/로그·API 키·runtime 접근키를 포함하지 않습니다. 시험용 runtime과 demo 출력도 verification에서 제외합니다. 기존 원본 공급자 파일은 읽기 전용이라는 동작을 유지했습니다.

## 미검증 / 제한

실제 사용자 DB, 설치된 VS Code Extension Host, Windows/macOS/WSL/SSH, 실제 청구액, 실제 Antigravity 비공개 필드 의미, OS PiP/파일 선택 창, 인터넷 카탈로그·배포 서비스, 24시간 장기 실행과 수백만 요청은 이 결과로 인증하지 않습니다.

수집기 RSS는 VS Code 전체·브라우저·별도 Python 프로세스 RAM 합계가 아닙니다. 중앙 저장소의 전체 JSON 이벤트 Map과 큰 측정·정렬은 아직 메모리를 사용합니다. 첫 수집/복구는 평상시보다 크고, 스트리밍 때문에 어떤 시작 경로는 느려질 수 있습니다. 완전한 메모리 누수 부재·무조건 일정 메모리·실제 카드 청구액 일치를 주장하지 않습니다.
