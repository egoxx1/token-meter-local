## 1. 설치할 파일

VS Code에는 **`token-meter-local-0.9.0.vsix` 하나만** 필요합니다. 소스 ZIP은 코드 수정·독립 실행용이고 all-files ZIP은 설치 파일·소스·설명서·검증 자료 묶음입니다.

1. VS Code → 확장 → `…` → **Install from VSIX…** → 0.9.0 VSIX 선택.
2. 작업 저장 후 **Developer: Reload Window**. 이전 브라우저 대시보드 탭은 닫습니다.
3. 하단 **TM**으로 다시 열고 **LOCAL / 0.9.0**을 확인합니다. 구버전이면 **Token Meter: Restart Collector**.

**기존 `~/.token-meter`와 `active-data.json`, `data-epochs`를 삭제하지 마세요.** 이번 버전 설치 자체는 데이터 초기화나 가격표 재산정을 하지 않습니다. 0.8.0의 활성 데이터·백업·초기화 기준점을 그대로 읽습니다. 원본 로그/DB에 코드를 복사할 필요도 없습니다. 기존 종료 측정은 보존합니다.

Marketplace 및 실제 배포 서버가 연결된 자동 배포가 아닙니다. 이번 파일은 수동 설치본입니다. 모델·가격표 자동 갱신과 서명 업데이트 엔진의 기존 설정은 유지합니다.

## 2. 화면 의미가 바뀐 부분 — 가장 중요

| 화면 | 토큰 | 사용금액 |
|---|---|---|
| **IN · 일반 입력** | 캐시 읽기·쓰기를 제외한 입력 | 일반 입력 단가로 계산된 금액 |
| **CACHE READ · 캐시 읽기** | 재사용한 캐시 입력 | 캐시 읽기 단가로 계산된 금액 |
| **CACHE WRITE · 캐시 쓰기** | 캐시에 기록한 입력 | 일반/5분/1시간 등 해당 조건의 쓰기 금액 합계 |
| **OUT · 출력** | THINKING을 포함한 전체 출력 | 전체 출력 금액 |
| **TOTAL** | 위 네 항목의 합계 | 네 금액의 합계 |

```
TOTAL = IN + CACHE READ + CACHE WRITE + OUT
OUT = 비추론 출력 + THINKING (+ 분해 미확인 출력)
```

**전 버전의 IN은 캐시를 포함한 입력 합계였습니다. 이번 화면의 IN은 일반 입력만입니다.** 따라서 IN 표시 숫자가 줄어도 누락이 아닙니다. 빠진 캐시 입력은 두 캐시 칸에 옮겨집니다. **전 버전 BILLABLE OUT은 이번 OUT**이고, THINKING을 OUT에 다시 더하지 않습니다. 총 토큰/총비용의 산식과 저장 단가는 그대로입니다.

대시보드 상단·도구·모델·프로젝트·측정 카드·비교·사용 이력·고정 하단바·PiP·VS Code 상태바·터미널 상태줄을 같은 순서로 맞췄습니다. 표는 각 칸에서 토큰과 사용금액을 함께 보여줍니다.

**`캐시 유지시간 · THINKING 상세`**를 펼치면 기존 추론 분해와 캐시 쓰기 5분/1시간/일반 세부값을 확인할 수 있습니다. 세부값은 추가 요금이 아닙니다. 기본 화면에서 중복될 수 있는 THINKING/BILLABLE OUT 카드를 별도로 나열하지 않습니다.

## 3. 단가와 사용금액

각 행은 **과금 항목 → 사용 토큰 → 적용 API 단가 → 사용금액**입니다. 기본 단위는 **USD / 100만 토큰 (1M = 1,000,000)**. 1,000토큰 기준으로 전환해도 표시 단가만 바뀌며 사용금액은 변하지 않습니다.

상단에 단가 대상 모델·공급자·모드를 표시합니다. 여러 조건이 섞이면 혼합으로 표시하고 **모델 · 단가 근거**에서 각 조건을 확인합니다. 근거는 해당 기록에 저장된 적용 단가이며 최신 카탈로그나 평균 단가가 아닙니다. 모델·가격표 매칭 검사도 그대로 사용할 수 있습니다.

**쓰기 사용량이 0이어도 확인된 쓰기 단가는 표시**합니다. 단가가 있는데 사용량이 없는 것과, 가격 자체를 모르는 것을 구분합니다. 5분/1시간이나 여러 모델의 쓰기 단가가 다르면 조건별 상세를 제공하며 단일 평균으로 바꾸지 않습니다.

합성 예시(일반 $2, 캐시 읽기 $0.20, 쓰기 $2.50, 출력 $10 / 100만):

| 항목 | 토큰 | 사용금액 USD |
|---|---:|---:|
| IN | 100,692 | 0.201384 |
| CACHE READ | 2,149,888 | 0.4299776 |
| CACHE WRITE | 0 | 0 |
| OUT | 10,619 | 0.106190 |
| TOTAL | 2,261,199 | 0.7375516 |

화면은 사용금액을 보통 소수점 6자리까지 표시하여 TOTAL은 `$0.737552`로 보입니다. 내부 합산은 정수 pico-USD 기준입니다. 예시는 10개의 짧은 합성 요청으로 구성했으며 사용자 원본 로그를 읽은 결과가 아닙니다. 이번 UI 변경에서 단가 자체나 비공개 필드 의미를 새로 검증한 것은 아닙니다.

## 4. 불확실한 값은 숨기지 않습니다

필수 단가가 없으면 **계산 불가 / 계산분**으로 표시합니다. 캐시 카운터가 없으면 **관측분·미기록 건수**를 남기고 실제 쓰기 0이라고 확정하지 않습니다. 이전에 고정된 측정에 입력 분류가 없으면 총액과 알려진 출력은 유지하되 일반 입력/캐시를 만들어 채우지 않습니다.

THINKING 분해가 불가능해도 확인 가능한 전체 OUT과 비용은 유지합니다. Antigravity는 여전히 비공개 SQLite 형식의 참고 해석이며, 세부 필드 해석과 원본 수집이 공식 청구서 수준으로 검증됐다는 뜻은 아닙니다.

## 5. 저장·삭제·재측정

기존 월별 `usage-log`, 최신 `ledger`, 측정, 설정과 전체 초기화의 데이터 epoch를 유지합니다. 화면을 바꿔도 과거 데이터를 삭제하거나 다시 청구하지 않습니다. 원본 데이터와 프롬프트/코드/추론 본문을 별도로 저장하지 않는 기존 정책도 같습니다.

**수정한 한 가지 계산표시 경로:** 도구/모델 초기화 행을 여러 측정 그룹으로 합칠 때 캐시 금액 상세가 빠질 수 있던 부분을 보완했습니다. 각 그룹의 저장된 입력 분류와 금액을 함께 묶습니다. 원래 전체 사용금액을 재가격하는 기능은 아닙니다.

측정 카드의 삭제, 선택 삭제, 측정 전체 삭제, 상단 전체 초기화는 그대로입니다. 확인 없이 실행하지 않습니다. 전체 초기화는 이전 데이터를 백업으로 보존하며, 원본 CLI 로그나 계정 사용량을 지우지 않습니다. [초기화 계약](docs/RESET-DELETE.md)

## 6. CSV/JSONL 호환성

기존 기술 필드 `input`은 **캐시를 포함한 입력 합계**를 유지합니다. 새 UI의 IN을 사용할 때는 **`normalInput`**을 읽습니다. `output`은 계속 THINKING 포함 전체 출력입니다.

내보내기에 `cacheWriteUsd`, `inputFieldMeaning: inclusive-of-cache`, `displayINField: normalInput`을 추가하고 요청 JSON에는 네 항목의 `billingView`를 제공합니다. 측정 CSV도 네 항목별 토큰/비용을 제공합니다. 이전 CSV 소비 코드에서 `input`을 캐시와 또 더하지 마세요.

## 7. 실행·테스트

VS Code 1.95+ 또는 독립 실행 Node.js 20+. Antigravity는 실행 Node의 `node:sqlite` 또는 SQLite 모듈이 있는 Python 3가 필요합니다. 외부 npm 실행 의존성은 없습니다.

소스 ZIP의 **token-meter** 폴더에서:

```sh
node bin/cli.js stop
node bin/cli.js serve --open
```

개발 검사:

```sh
npm test
npm run check
npm run package
# 별도 임시 데이터를 사용하는 demo를 먼저 실행
node bin/cli.js demo
# 위 명령이 출력한 데이터 경로 사용. 일반 사용자 데이터에는 실행 거부
python3 scripts/billing-smoke.py /path/to/demo --offline --output /tmp/billing-ui
python3 scripts/data-reset-smoke.py /path/to/another-fresh-demo --offline --output /tmp/reset-ui
```

UI 시험만 Python Playwright/Chromium이 필요합니다. `--offline`은 about:blank에 실제 앱을 렌더링하고 실제 로컬 API로 연결하는 제한된 시험입니다. 기존 레이아웃 전용 시험은 `docs/legacy-ui-tests-0.8.0`에 보관했고 현재 실행 대상은 위 두 파일입니다.

이번 확인: **Node 341개, UI 52개(요금표 33 + 삭제/초기화 19), JavaScript 60개 구문 검사**. 실제 VSIX 설치, 사용자 DB/계정/청구서, Windows/macOS, 브라우저 정상 URL 탐색/CSP·OS 최상위 PiP 실기는 검증하지 않았습니다. [검증 보고서](docs/TEST-REPORT.md)

금액은 **API 환산·추정 토큰 비용**이고 실제 구독 결제액이 아닙니다. 원래의 모델/수집 제약·계정 잔여량 미지원·전체 JSON 저장소의 대규모 성능 한계·수동 환율·여러 기기 미동기화는 유지합니다.
